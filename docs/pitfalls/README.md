# Pièges et leçons

Erreurs déjà faites et leur solution, par thème, écrites pour servir à **n'importe quel jeu**, pas seulement à celui où ils sont apparus (les épisodes cités viennent de *River Cleaner: India* et servent d'exemples ; les fichiers qu'ils nomment sont dans ce dépôt-là). Les relire avant de travailler sur un thème ; y ajouter une entrée dès qu'une erreur fait perdre du temps ou risque de revenir, dans le fichier de son thème.

Format d'une entrée : **symptôme**, **cause**, **bonne pratique** (pour `methode.md` : **leçon**, **ce qui s'est passé**, **pratique**).

- `methode.md` : la façon de travailler (mesurer, concevoir pour l'échelle, décisions, essais, ce que Claude ne peut pas juger). À lire au début de tout nouveau projet.
- `godot-gdscript-et-scenes.md` : GDScript typé, scènes, ressources, import, shaders.
- `godot-ligne-de-commande-et-export.md` : Godot sans éditeur (`--script`, `--headless`), captures, vidéos, export.
- `tests.md` : gdUnit4, tests de scénario, isolation entre tests.
- `physique.md` : Jolt, collisions, objets qui flottent ou se posent.
- `rendu-et-performance.md` : rendu, transparence, mesure de performance.
- `ci-et-session-cloud.md` : GitHub Actions, runners, session cloud, réseau.
- `modeles-3d.md` : images de référence, Blender, Tripo, import des modèles dans Godot.

Ce qu'un nouveau jeu reprend dès le premier jour : le modèle lui-même, et `docs/lecons-river-cleaner.md`.
